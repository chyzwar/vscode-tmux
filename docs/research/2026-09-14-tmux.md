# tmux as the session backend

Sources: tmux.1 (3.2a and 3.4), tmux sources (`cmd-switch-client.c`, `server-client.c`, `session.c`, `control-notify.c`, `cmd-queue.c`, `tmux.c`, `client.c`), CHANGES, Control-Mode wiki, tmux-resurrect/continuum scripts, Ghostty `termio/Exec.zig` and shell-integration scripts, tmux issues #4931/#5237, Ghostty discussions #11433/#10387. Ubuntu 22.04 apt: **3.2a**; 24.04: 3.4; latest 3.8.

## Switching a client to another session

`tmux -L vscode-tmux switch-client -E -c /dev/pts/7 -t '=project-a-4e830601'`
- `-c` is mandatory from a daemon (no `$TMUX`/tty to infer from). Client name = pty path from `list-clients -F '#{client_name} #{client_tty} #{client_pid} #{client_session} #{client_termname} #{client_control_mode}'`.
- `-t '=name'` forces exact match (plain names also prefix/fnmatch-match).
- In place and immediate: `tc->session = s; notify client-session-changed; redraw`. Each session's current window is untouched (session state), so switching back restores the previously selected tab.
- `-E` skips `update-environment` copying the client's env into the session.
- Identify the Ghostty client: `client_termname == xterm-ghostty` (Ghostty exports `TERM=xterm-ghostty`, `TERM_PROGRAM=ghostty`), or a marker env var on the attaching command, and `client_control_mode == 0`.

## Observing state

- Hooks that fire in 3.2a/3.4: `client-attached`, `client-detached`, `client-session-changed`, `session-created/closed/renamed`, `session-window-changed`, `window-linked/unlinked/renamed`, `window-pane-changed`, `pane-exited/died`, ... `after-*` hooks exist only for a limited command set (no `after-select-window`, `after-new-window` in 3.4).
- Control mode (`tmux -C attach -t lobby -f no-output`) streams `%client-session-changed <client> $id name` (all clients), `%session-window-changed $id @id`, `%sessions-changed`, `%window-add/close/renamed` (observer's session), `%unlinked-window-*` (other sessions). Subscriptions: `refresh-client -B name:@*:'#{...}'` (observer's session only). Control clients do not affect session sizes since 3.3; pass `-f ignore-size` on 3.2a. Prefer control mode over `run-shell` hooks for a daemon.

## Per-session environment

`new-session -d -s NAME -c DIR -e K=V -e K2=V2` (3.2+) puts vars in the session environment; every later `new-window`/`split-window`/`respawn-*` in that session inherits them. `set-environment -t '=NAME' K V` for later changes. Running panes never receive updates. The global environment is the daemon's environment at server start: start the server from a sane, scrubbed env.

## Tab bar and config isolation

`tmux -L vscode-tmux -f our.conf`: the first `-f` replaces the default config list, so neither `/etc/tmux.conf` nor `~/.tmux.conf` loads. Options: `status-position top`, `status-left ''`, `status-right ''`, `window-status-format`, `window-status-current-format`, `window-status-separator ''`, `mouse on` (click to select), `automatic-rename off`, `allow-rename off` (OSC titles only set pane titles anyway), `set-titles on` + `set-titles-string '#S — #W'`. `destroy-unattached off` (default), `exit-empty off` (keep server), `detach-on-destroy off`. `default-terminal tmux-256color`, `terminal-features 'xterm-ghostty:RGB,...'`, `extended-keys on`, `set-clipboard on`, `focus-events on`. 3.2a lacks `allow-passthrough` (3.3), OSC 8 hyperlinks (3.4), `client-active` (3.3).

## Naming and windows

Session names: `:` and `.` are rewritten to `_`; keep to `[A-Za-z0-9_-]`. `new-window -d -t '=S:' -n NAME -c DIR -e K=V -P -F '#{window_id}' [cmd...]` returns the stable `@N`. `select-window -t '=S:@N'`, `rename-window`, `kill-window`, `list-windows -t '=S' -F '#{window_id} #{window_index} #{window_name} #{window_active} #{pane_current_path} #{pane_current_command} #{pane_pid} #{pane_dead}'`. `remain-on-exit on|failed` + `respawn-window -k` for "restart command". `has-session -t '=S'`.

## Persistence across reboot

tmux keeps nothing. tmux-resurrect writes tab-separated pane/window/state lines and restores with `new-session`/`new-window`/`send-keys`; continuum saves every 15 min via `status-right`. No server-exit hook exists (3.4 or 3.8). A custom JSON snapshot in the daemon, updated from control-mode events and rebuilt with the same primitives, is simpler for this data model.

## Ghostty specifics

`xterm-ghostty` terminfo is resolved by the tmux *client* (Ghostty sets `TERMINFO`), so the server needs no entry. Ghostty shell integration is not auto-injected inside tmux; OSC 133 features (jump to prompt, notify on finish, prompt-aware close) do not pass through tmux (nicm: "not something tmux is going to be able to do"). Derive prompt state from tmux instead, and set `confirm-close-surface = false`.

## Exit semantics

Closing the Ghostty window detaches the client; sessions survive (`destroy-unattached off`). `exit-empty on` is the default → set off. `detach-on-destroy on` would close the Ghostty client when its session is killed → set off (or switch first).
